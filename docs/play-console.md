### Foreground service declaration
The service is `OverlayService`, typed `specialUse|microphone` in the manifest. Declare both types. For each type, Play asks for a description, the user impact if the task is deferred or interrupted, and a video link ([Play Help 13392821](https://support.google.com/googleplay/android-developer/answer/13392821)).

**specialUse**
- **Manifest subtype** (`PROPERTY_SPECIAL_USE_FGS_SUBTYPE`): "Persistent on-screen companion character: a small animated overlay the user can move and tap to talk to the assistant."
- **Description:** Bibi is a floating companion character that stays on screen over other apps after the user turns on Floating Bibi in the app. The service keeps the character's window on screen and shows a persistent notification with Hide, Open chat and Turn off. It starts only from the app's switch, and the user can stop it at any time.
- **If deferred:** the character doesn't appear until the service starts; the in-app chat still works.
- **If interrupted:** the character disappears until the app is opened again; nothing is lost, because chats are saved.

**microphone**
- **Description:**
  - Voice commands for the assistant, never saved.
  - The microphone records only after the user taps the floating character (tap-to-talk) or holds the talk button in the chat card.
  - It stops when the user pauses, after 8 seconds of silence, or on tap.
  - Audio is turned into text on the device and discarded.
  - The type is added only when the user has granted the microphone permission and the app is in front.
- **If deferred:** the user's speech isn't heard; the bubble keeps showing "Waking up…" and the user can type instead.
- **If interrupted:** the current spoken turn is lost; the user taps again.
- **Video checklist** (one video covers both types; unlisted YouTube link):
  1. In the app, turn on Floating Bibi and allow "Display over other apps".
  2. Show the persistent notification.
  3. Go to the home screen and tap Bibi: the bubble shows "Listening…" and Android's green microphone indicator appears.
  4. Ask a question, then show the spoken answer and the reply bubble.
  5. Stay quiet: the talk ends, the microphone indicator goes away.
  6. Long-press Bibi: the chat card opens; hold the talk button in it.
  7. Use the notification's Turn off: the character and notification disappear.

## 2. Permissions (merged release manifest)

| Permission | Why | When it's asked |
|---|---|---|
| `SYSTEM_ALERT_WINDOW` | Floating Bibi over other apps | Only when the user turns on Floating Bibi, after an in-app explanation; Android's settings page grants it |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | Keep floating Bibi on screen | Normal permissions, no prompt |
| `FOREGROUND_SERVICE_MICROPHONE` | Tap-to-talk and the card's talk button over other apps | Normal permission, no prompt |
| `RECORD_AUDIO` | Voice input | First mic use in the app, after a one-line explanation |
| `POST_NOTIFICATIONS` | The floating-Bibi notification | Onboarding step 3; "Not now" works |
| `com.android.alarm.permission.SET_ALARM` | Opens the Clock app to set an alarm or timer the user asked for | Normal permission, no prompt; no exact-alarm permissions |
| `WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED` | From WorkManager (daily memory clean-up, chat summaries) | Normal permissions, no prompt |
| `<queries>` for `MAIN`/`LAUNCHER`, `SET_ALARM`, `SET_TIMER` | "Open <app>" and the Clock app | Not a permission; listed for completeness |

Not used: `INTERNET`, SMS, call log, contacts, location, Accessibility, `USE_EXACT_ALARM`, `SCHEDULE_EXACT_ALARM`.
